## 一、這個網站要解決什麼

網站不是「把 16 個頁面做出來」，而是**讓三類人各自在 30 秒內得到他要的答案**。

| 評價視角 | 他其實在問什麼 | 網站要給的證據 |
|---|---|---|
| 課程評分人 | 功能要求是否真的走得通 | 三條鏈路可完整走完，不是靜態截圖 |
| B 端採購決策者 | 這家公司的東西能不能買、買了之後誰管 | 規格、報價、交期、服務邊界、「不包含」什麼 |
| 內部員工 / 會員 | 我登入之後能做什麼 | 登入後有明確身分呈現與下一步 |
| 一般訪客 | 這家公司是幹什麼的 | 首屏一句話講清：IoT 硬件 + 邊緣網關 |

**核心判斷**：本站的差異化不在頁面數量（16 頁只是及格線 +1），而在**克制**——不用「顛覆」「賦能」，改用可驗證的數字與明示的服務邊界。這一點必須貫穿到每一頁的文案與每個 CTA。

## 二、用戶與場景

| 角色 | 核心訴求 | 入口 | 落點 | 成功判定 |
|---|---|---|---|---|
| 企業採購 | 三款產品規格差異、單價、交期 | 首頁 01 四宮格 / 導航「產品」 | `products` → `product-detail?code=` | 能拉到採購單，或提交配置諮詢 |
| 樓宇 / 物業 | 能耗如何分攤、報表能否對接財務 | 首頁 03 創新專區 / `services` | `services` → `contact` | 提交諮詢表單 |
| 個人住戶 | 價格門檻、安裝難度 | 首頁 ticker / `products` | `product-detail` | 加入採購單 |
| 內部員工 | 登入、工單、文檔 | 導航右側「登入」 | `login` → 回首頁 | 導航顯示身分 |
| 課程評分人 | 表單提交跳頁、購買跳頁、站點地圖 | `sitemap` | 三條鏈路 | 全流程無斷點 |

**場景優先級**：課程評分人 > 企業採購 > 個人住戶 > 內部員工。
理由：這是作業，評分人是第一讀者；但文案口吻必須維持 B 端可信度，不能為討好評分人而寫成 demo 腔。

## 三、信息架構

### 3.1 現狀（已建成，不改結構）

```
一級  index（主菜單入口 + 品牌簡介 + 產品線 + 動態 + 數據 + CTA）
二級  about / products / services / support / news / contact / careers
三級  product-detail?code=S1|G2|E3
功能  login / register / register-done / cart / order-confirm / sitemap / 404
```

### 3.2 導航決策

**全局導航固定 6 項**：關於 / 產品 / 服務 / 支持 / 動態 / 聯繫。16 頁全部平鋪會失焦，二級以下靠頁內鏈與頁腳承接。

**右側功能區必須存在**（本輪新增決策）：目前右側只有「登入」一顆按鈕，購物車與身分無處可去。策劃上把右側定義為**功能區**，容納三件事：

| 位置 | 內容 | 狀態 |
|---|---|---|
| 右側 · 第 1 位 | 購物車圖示 + 件數角標 | ❌ 缺 |
| 右側 · 第 2 位 | 登入 / 會員名 + 登出 | ⚠️ 只有登入，無身分 |

> 這一改動**不新增頁面**，只補 HTML 掛點 —— `cart.js` 的 `[data-cart-count]` 與 `auth.js` 的 `[data-session-name]` / `[data-session-box]` 都已實作好，只是 16 頁沒有任何一頁掛上去。屬「已付費未使用」的現成能力。

## 五、內容模型

### 5.1 產品（`product-detail` 由 `?code=` 驅動）

固定六段，順序不可調換：

```
型號 + 中英名 → 4 條核心規格 → 完整規格表（10 項）
→ 交付清單（含什麼 / 不含什麼）→ 價格與交期 → 加入採購單
```

- 型號寫法全站統一：`S1` / `G2` / `E3`，等寬字體
- 價格一律 HK$，交期一律「工作日」
- G2 / E3 額外掛創新模組區（紫色），S1 不掛 —— 這是青紫分工的敘事依據，不能為了對稱而給 S1 硬加

### 5.2 新聞（`news` + 首頁廣播區）

4 頻道 × 每頻道 5 條 + 1 條主推：`CH01 綜合 / CH02 產品 / CH03 合作 / CH04 認證`。
每條必帶**具體數字或型號**（「1,200 台」「±0.5%」「720 小時」），避免「取得重大進展」這類空話。

### 5.3 服務（`services`）

每項服務三段：**做什麼 / 收費 / 不包含什麼**。
「不包含」是本頁最有價值的部分 —— B 端客戶真正會問的是邊界，不是賣點。

### 5.4 數據（首頁 04）

8 個指標必須**同源可追溯**（2026-09-30 營運記錄），且與產品頁規格不矛盾：
`50,000+ 設備` / `99.9% 連接率` / `0.02s 延遲` / `72h 緩存` / `8 併發` / `12 回路` / `148 員工` / `4.2h 響應`。

## 六、路徑策劃

三條鏈路是評分核心，**每條都必須有入口、有過程、有回流**。

```
鏈路一 註冊
  contact / 頁腳 / 導航 → register → 校驗 → register-done → 回首頁
  斷點：register-done 之後沒有「登入」引導，用戶拿到會員編號卻進不去系統

鏈路二 購買
  products → product-detail → 加入採購單 → cart → 結算 → order-confirm
  斷點：cart 無常駐入口。離開購物車後，只能回到某個產品頁再加一次

鏈路三 身分
  login → 寫入會話 → 全站導航顯示身分
  斷點：身分渲染 API 已寫好，但 16 頁都沒掛，實際永遠顯示「登入」
```

**回流設計原則**：任何終點頁（`register-done` / `order-confirm`）都必須給兩條出路 —— 一條回主流程，一條回內容。目前 `order-confirm` 有列印 + 回首頁，`register-done` 缺「去登入」。

> **G1 / G2 的性質**：不是缺功能，是**功能已寫好但沒接上**。這兩條修完，網站從「頁面齊全」變成「流程閉環」，性價比最高。

## 八、本輪策劃結論

| 編號 | 決策 | 結論 |
|---|---|---|
| D-01 | 頁面總數 | **凍結在 16 頁**，不新增 `privacy` / `terms` / 會員中心 |
| D-02 | 功能入口 | 導航右側擴為「功能區」：購物車（含件數）+ 登入/身分 |
| D-03 | 身分落點 | 登入後回首頁並在導航顯示會員名，**不建會員中心頁** |
| D-04 | 缺口處理 | 依 P0 → P1 → P2 順序修，P2 可選 |
| D-05 | 視覺體系 | 不動。V1.1.1 + 康陶硬參數已定案，本輪只補結構不碰皮 |
| D-06 | 組件優先於體驗 | **評分表點名的五項 JS 組件優先於任何體驗優化**（G7–G9 升 P0，G1–G3 降 P1） |
| D-07 | 動態背景改版 | **緩辦**。原提示詞 v3 未交付，且與五項組件爭時間；待組件補齊後再評估 |
| D-08 | 文案紅線 | 授權例外，僅限 G3（缺陷修復）與 G6（去重）。其餘文案不動 |

**D-01 的理由**：課程要求 15 頁，16 頁已達標。再加頁只會攤薄質量，且 `privacy` / `terms` 對評分無實質加分；頁腳已有的免責說明足以覆蓋。

**D-03 的理由**：會員中心是另一個產品，不是這一輪的事。用導航身分 + 回首頁，花 0 頁解決「登入之後呢」的問題。

## 九、迭代路線

### P0 · 補齊評分表點名的三項組件

| 項 | 落點 | 動作 | 驗收標準 |
|---|---|---|---|
| G7 | `support.html` 六條 FAQ | 靜態卡片改為單開手風琴（同時只開一項） | 點擊展開／收起；`aria-expanded` 同步；鍵盤可操作；預設全收起 |
| G8 | `index.html` `.mn-hero__visual` | 靜態 `network.svg` 改為三幀輪播（S1 / G2 / E3） | 自動 4000ms 切換；圓點可點；左右可切；懸停暫停；`reduced-motion` 下靜止 |
| G9 | `products.html` `.card__media` | 圖片懸停放大 + 青色描邊 + 亮度提升（不新增任何文字） | 純 CSS 實現；`transition` 0.4s ease；不引起佈局位移 |

**為什麼是這三個落點**：
- FAQ 內容已寫好六條，改結構不改文案，成本最低而收益最直接
- 首屏是最顯眼的展示位，輪播放這裡評分人一眼能看到
- 產品卡本來就有圖，補 hover 只需幾行 CSS

### P1 · 流程閉環

| 項 | 動作 | 驗收標準 |
|---|---|---|
| G1 | 導航右側加購物車入口 + `[data-cart-count]` 角標 | 任意頁面可進購物車；加購後角標即時變化 |
| G2 | 登入按鈕外包 `[data-session-box]`，內含 `[data-session-name]` | 登入後顯示會員名；登出後恢復「登入」 |
| G3 | 改寫 `login.html` toast 文案 | 無「建設中」字樣，無簡體 |

> G1 / G2 的腳本策略：**不新增 script 標籤**。`cart.js` 目前僅 2 頁、`auth.js` 僅 7 頁，若為角標補到 16 頁會多 23 個引入。改為把角標與身分渲染併入 `main.js`（16 頁已有），只讀 `localStorage`，不依賴另兩個檔案。
