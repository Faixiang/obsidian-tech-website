## 四、色彩設計（約 400 字）

### 4.1 深色分級背景（5 級縱深）

| 層級 | 色值 | 角色 |
|---|---|---|
| 極夜藍 | `#02020A` | 全域最深、頁腳 |
| 深空藍 | `#0B1F3A` | 主背景、導航、Hero |
| 藍灰 | `#16294A` | 次級區塊 |
| 石墨灰 | `#1C2530` | 卡片/面板底 |
| 金屬藍灰 | `#1E2A44` | 卡片 hover、高亮面板 |

設計原則：頁面至少使用 3 級深色形成縱深，相鄰層級須可辨。

### 4.2 雙強調色

- 電光青 `#00D4B8` — 科技、連線、在線、主行動
- 霓虹紫 `#7B2FFF` — 創新、未來、賽博、次級行動

**分工規則**：同一區塊內青紫不混用；主鏈路（購買、註冊、登入）全青，
創新/未來敘事區塊全紫。

### 4.3 對比度實測與自動求解（**最重要加分點**）

實作時發現：設計規範自定的對比度標準，部分色值並未達到規範自己要求的數值。
因此寫了一個按 WCAG 2.1 相對亮度公式運作的求解器（`docs/contrast.py`），
**保持色相不變，僅沿亮度軸搜索首個達標值**。

#### 規範聲明值 vs 實測值

| 組合 | 規範要求 | 規範值實測 | 判定 |
|---|---|---|---|
| 白字 / 深空藍 `#0B1F3A` | ≥ 7:1 | 16.52:1 | 達標 |
| 深空藍字 / 雲白 `#F5F7FA` | ≥ 7:1 | 15.39:1 | 達標 |
| 電光青 `#00D4B8` / 深空藍 | ≥ 4.5:1 | 8.74:1 | 達標 |
| 深紫 `#2E1065` / 淡紫 `#E9D5FF` | ≥ 4.5:1 | 11.19:1 | 達標 |
| **霓虹紫 `#7B2FFF` / 深空藍** | ≥ 4.0:1 | **2.90:1** | **未達標** |
| **亮紫 `#A855F7` / 深空藍** | ≥ 4.5:1 | **4.17:1** | **未達標** |
| **鋼灰 `#6E7B91` / 雲白** | ≥ 4.5:1 | **3.99:1** | **未達標** |

#### 規範未覆蓋但必然用到的組合

| 組合 | 實測 | 問題 |
|---|---|---|
| 電光青 / 雲白 | 1.76:1 | 淺底區塊的青色連結會「看不見」 |
| 霓虹紫 / 藍灰 | 2.76:1 | 紫色專區若用藍灰底，紫字不可讀 |
| 鋼灰 / 深空藍 | 3.86:1 | 頁腳輔助文字全面不達標 |
| 金色 / 雲白 | 2.14:1 | 淺底金字不可用 |

#### 求解結果（色相完全不變）

| 變量 | 色值 | 用途 | 實測 |
|---|---|---|---|
| `--on-cloud-cyan` | `#00806F` | 淺底青色連結、次按鈕 | 4.53:1 |
| `--on-deep-purple` | `#9558FF` | 深底紫字（大字號） | 4.03:1 |
| `--on-deep-bright` | `#AD5EF7` | 深底亮紫正文 | 4.50:1 |
| `--on-cloud-steel` | `#667286` | 淺底鋼灰文字 | 4.53:1 |
| `--on-deep-steel` | `#7B879B` | 深底鋼灰文字 | 4.55:1 |
| `--on-graphite-steel` | `#808C9F` | 石墨灰底鋼灰 | 4.55:1 |
| `--on-cloud-success` | `#1D815A` | 淺底成功態 | 4.51:1 |
| `--on-cloud-warn` | `#D03B00` | 淺底警告態 | 4.54:1 |
| `--on-cloud-danger` | `#D92C1B` | 淺底錯誤態 | 4.52:1 |
| `--on-cloud-gold` | `#876F29` | 淺底金色 | 4.51:1 |

#### 另一處修正：深色縱深

規範要求「相鄰層級對比 ≥ 0.5 亮度差」，但藍灰 `#12233F` 與石墨灰 `#1C2530`
的亮度差僅 **0.0009**，肉眼幾乎無差別，「解決層級單調」的目標反而沒達成。
將藍灰調整為 `#16294A` 後，ΔY 提升至 0.0075，層級可辨。

#### 結論

**規範也需要被驗證。** 發現問題並修正，比照抄規範更有價值。
求解器已成為專案的常駐工具：CSS 中的顏色變體全部由它生成，不手填、不手改。

> **寫作提示**：這一節最能體現「深度思考」。
> 不要只寫「我遵守了規範」，要寫出「我驗證了規範，發現三處不合理，於是寫工具自動求解」
> —— 這展示的是**工程思維**，不只是審美。

## 五、佈局與排版（約 300 字）

### 5.1 柵格系統

- 12 欄柵格，桌面間距 16px / 行動端 8px
- 內容最大寬度 1280px 置中
- 間距基數 4px（4/8/12/16/24/32/48/64/80）
- 大區塊留白 80px，形成縱向節奏

### 5.2 字體層級

| 層級 | 字號 | 字重 | 行高 |
|---|---|---|---|
| Display / H1 | 40–56px | 700–900 | 1.2 |
| H2 | 28–36px | 700 | 1.3 |
| H3 | 20–24px | 600 | 1.4 |
| 正文 | 14–16px | 400 | 1.6–1.8 |
| 輔助說明 | 12–13px | 400 | 1.5 |
| 英文標籤 Eyebrow | 11–13px | 500–700 | 1.4 |

Eyebrow 為本站新增的層級：英文小寫大寫 + 0.12em 字距，用於產品型號與區塊編號。

### 5.3 圓角與陰影

- 按鈕 4px（克制）/ 卡片 8px / 模態 12px
- 卡片陰影極淡，避免與內容爭奪注意力

### 5.4 響應式策略

- 斷點：1000 / 960 / 720 / 640 / 560
- 導航在 960px 摺疊為漢堡選單，並鎖定背景滾動
- 柵格 3 欄 → 2 欄 → 1 欄

## 六、使用者友善性（約 300 字）

### 6.1 導航與可發現性

- 全站頁頭、頁腳雙入口，導航收斂為 6 項
- 當前頁以電光青下劃線標示
- 獨立站點地圖頁，列出全部頁面與層級
- 頂部 2px 滾動進度條，提供位置感

### 6.2 表單設計

- 必填項以紅星標註
- **失焦即校驗**，不必等提交才發現錯誤
- 錯誤訊息緊鄰欄位下方，說明具體問題
- 校驗失敗時焦點自動移到第一個錯誤欄位
- 聯繫頁採三Tab 分欄：諮詢 / 評論 / 投訴

### 6.3 無障礙設計（**重要加分點**）

- 跳轉連結（Skip Link），鍵盤使用者可直接跳至主內容
- `:focus-visible` 可見焦點環
- 尊重 `prefers-reduced-motion`，系統開啟減弱動效時自動關閉動畫
- 語義化標籤：`header`/`nav`/`main`/`footer`/`section`
- 圖片均有 `alt`，裝飾性圖示標 `aria-hidden`
- 資料表格配 `caption` 與 `scope`
- 繁體中文統一（`lang="zh-Hant"`）

### 6.4 反饋機制

- 輕提示（Toast）取代瀏覽器原生 `alert`
- 訂單確認頁提供列印/存 PDF 入口

## 七、網路安全風險與建議（約 350 字）

> **本節為 CIS282 重點，寫深一點。**

### 7.1 本專案的安全風險

| 風險 | 說明 | 緩解措施 |
|---|---|---|
| 密碼明文傳輸 | 表單直接提交 | 真實系統必須 HTTPS |
| 密碼明文儲存 | 若存 localStorage 明文可被讀取 | 加鹽雜湊（Bcrypt/Argon2） |
| XSS | 使用者輸入渲染到頁面 | 已用 `esc()` 轉義 |
| 工作階段固定 | 登入後沿用舊標識 | 登入後重新產生工作階段 |
| 無 CSRF 防護 | 表單可能被跨站提交 | 同源權杖 + SameSite Cookie |
| 用戶端資料可竄改 | localStorage 全由前端控制 | 關鍵資料須伺服器端校驗 |
| 敏感資訊洩漏 | 不應在 URL 傳密碼/卡號 | POST + HTTPS + 不寫日誌 |

### 7.2 靜態站點的固有局限

- **前端校驗只是體驗，不是安全**：任何客戶端校驗都可被繞過
- `localStorage` 無過期機制、隨瀏覽器清除而消失、同域下所有指令碼可讀
- 本專案的定位是**課程演示原型**，真實產品必須有後端

### 7.3 真實系統的架構建議

```
前端（HTML/CSS/JS）
    ↓ HTTPS + JSON
API 層（認證、輸入校驗、限流、CSRF 校驗）
    ↓
業務層（訂單、價格計算、權限判定）
    ↓
資料庫（密碼雜湊儲存、敏感欄位加密、稽核日誌）
```

### 7.4 使用者側提醒

- 網站從不索取密碼或驗證碼
- 不以任何理由要求轉賬
- 註冊資料僅存本機，可隨時清除

## 八、技術實作（約 300 字）

### 8.1 技術選型

- 原生 HTML5 + CSS3 + JavaScript，不引入框架
- 理由：課程要求掌握基礎技術；且無依賴更易部署

### 8.2 無伺服器方案

- 表單跳轉鏈路用 `localStorage` 承接
- 三條鏈路：註冊、購買、身分
- 局限與替代方案（見第七章）

### 8.3 工程實踐

- CSS 變數統一設計令牌，改主題只改變數值
- JS 模組化：`auth.js` / `cart.js` / `main.js` 職責分離
- **對比度求解器常駐專案**，色彩變體由腳本生成而非手填
- SVG 手繪素材，零外部依賴、零失效風險
- Git 版本管理 + 工程日誌與提交記錄對應
